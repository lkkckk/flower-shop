# 订单照片与移动端适配

新建或编辑预售单，添加商品后，在「订单确认照片」中为每件商品上传一张照片，保存订单后生效。支持 JPG、PNG、WebP，单张最多 10MB。上传失败保留原照片，上传过程中禁止保存订单。

上传照片使用独立且不覆盖的文件名，订单明细的 `imageUrl` 保存该地址。新订单带入的本地商品照片也会复制到订单照片目录。详情及配送单只读取订单明细照片，不再回退到当前商品主图；明确移除照片会保存为空。旧单没有照片时显示无图，可在允许编辑的状态补传。旧的外部图片地址须上传本地照片或移除后才能重新保存。

照片可以在允许编辑商品清单的状态更换；进入制作及后续状态、或取消后沿用原有清单锁定规则。该功能固定订单图片与商品图库的关系，不是客户签字确认或完整的图片修改审计系统。先前照片文件保留，未保存订单的上传文件也不会自动删除。

配送单先预览，待店名与全部照片加载完成后点击「打印预售单」。照片加载失败会禁止页面打印按钮并提供重试，照片按原比例完整显示。小票与配送单优先读取设置页的 `storeName`，兼容历史 `shopName`、`shop_name`；收银员可读取打印店名。

照片通过运行时路由 `/preorder-images/:filename` 读取，发布后上传及服务重启均不依赖构建时静态资源清单。生产环境建议配置 `PREORDER_IMAGE_DIR` 为持久化绝对目录；未设置时使用 `PRODUCT_IMAGE_DIR` 同级的 `preorder-images`（默认 `public/preorder-images`）。备份数据库时一起备份商品和订单照片目录，发布时保留它们。

移动端保留现有配色。手机下预售表单单列排列，表格在自身区域横向滚动并取消遮挡内容的固定列；平板保留合适的多列布局。盘点、报表、详情抽屉、选品弹窗、设置表单及日期弹层补齐窄屏布局。

## 验证

- `node --import tsx --test tests/preorder-images.test.ts tests/product-images.test.ts tests/pos-quantity.test.ts`
- `tests/preorder-acceptance.mjs` 使用 `tests/prepare-pos-acceptance.mjs` 创建的独立 PostgreSQL schema，校验上传鉴权、真实文件读取、订单新建和编辑持久化、换主图隔离、清空图片、制作后锁定、收银员店名读取。需把独立验收账号设为管理员并设置测试店名；默认请求 3010，可通过 `TEST_ORIGIN` 指向构建服务。
- 浏览器检查 390px 手机与 768px 平板页面，操作照片上传、保存、详情和打印预览；另检查 58mm 小票店名。
- 本轮验证为本地构建、API、数据库与浏览器验证，不含 VPS 发布、实体手机 Safari 或纸质打印机实打。
