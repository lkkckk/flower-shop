# 浏览器收银与小票打印

## 操作

直接访问 `/pos`，无需安装或封装应用。电脑及平板横屏显示右侧清单；窄屏使用底部购物车及结账栏。

1. 按分类或花名、颜色、规格搜索商品。
2. 选择销售单位，点击加号加入 1 个销售单位；点减号减少，点击已选数量可批量输入。不同单位分别列在清单中，共享该商品的基础库存。
3. 默认散客，可从顶部选择客户。优惠、支付方式、实收在结账面板确认。
4. 结账成功后商品库存刷新，清单清空。点击“查看 / 打印 58mm 小票”进入小票页，也可用“上笔小票”重开。
5. 小票页由用户点击“打印小票”调用浏览器系统打印，不依赖结账后的延时弹窗。

零售基础价与当前后端一致，整单优惠在结账时计算。服务器重新计算数量换算、应收及欠款，价格已变化时要求重新确认。并行清单不预占库存；跨商品配方共享原料等情况仍由结账事务校验。

挂单在本次页面会话内保留，刷新或关闭浏览器不提供持久挂单保证。

## 58mm 打印

默认纸宽 58mm，内文宽约 52mm，可切换 80mm。预览采用实际毫米宽度，打印时隐藏操作区域。打印驱动仍需选择实际卷纸规格、合适缩放并关闭页眉页脚；网页不能强制驱动纸张长度或自动切纸。

**iPad + 普通蓝牙小票机不能等同于支持浏览器直接打印。** Safari 的系统打印通常通过 AirPrint，须核对具体型号支持及网络配置。[Apple：使用 AirPrint 打印](https://support.apple.com/en-ca/109349)。仅有蓝牙或 Wi-Fi 功能不代表支持 AirPrint。

当前已实现浏览器打印入口和小票排版，尚未实现蓝牙驱动、ESC/POS、打印任务队列或电脑打印服务。未连接实体打印机验证出纸。

继续使用普通蓝牙打印机，可按具体型号评估以下路径：

- 厂商明确支持网页调用的打印方案：核对支持的浏览器、型号和接口。
- 店内 Windows 电脑转发：电脑连接打印机并安装驱动/打印服务，网页把订单号提交给服务端，再由电脑处理任务。iPad 只需浏览器。实施前需确认型号及电脑是否常开。
- 更换为明确支持 AirPrint 的设备：由 iPad 系统面板打印，仍需要用户选择打印机并确认。

后续若实现电脑转发，需要记录任务状态、失败原因及防重复机制；“任务已提交”不能作为“实体出纸成功”的证据。

## 本地验收

基础数量和金额回归：

```powershell
node --import tsx --test tests/pos-quantity.test.ts
```

端到端验收使用独立 PostgreSQL schema。准备脚本只创建新的 `pos_acceptance_<时间戳>`，不改动店铺 public schema。测试数据不会自动清理。

```powershell
node tests/prepare-pos-acceptance.mjs
# 停止其他占用 3000 端口的开发服务后：
node --env-file=.cache/pos-test.env node_modules/nuxt/bin/nuxt.mjs dev --host 127.0.0.1 --port 3000
# 另开终端：
node tests/pos-checkout-acceptance.mjs
```

验收账号仅存在于隔离 schema，定义在准备脚本中。每次完整重跑先重新准备 schema；接口测试会校验 schema、验收账号和商品数量，失败则停止。

恢复店铺服务应停止测试实例，使用原 `.env` 启动。不要将 `.cache/pos-test.env` 用于实际收银。
